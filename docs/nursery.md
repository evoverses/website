# Local Nursery implementation

Website branch: `dan-dev`. Source: `apps/website/src/app/nursery` and `apps/website/src/components/nursery`.

- `/nursery`: Marketplace-style Bertha and Hermann character cards.
- `/nursery/bertha`: connected-wallet Evos, sequential compatible parents, individual and combined EVO prices, current AVAX randomness surcharge, breeding and egg collection.
- `/nursery/hermann`: owned egg gallery, treatment, three-day incubation, hatch request and final hatch. A token-number lookup recovers eggs before indexer updates.

## Deployment configuration

Set `NEXT_PUBLIC_BREEDER_BERTHA_ADDRESS` and `NEXT_PUBLIC_HATCHER_HERMANN_ADDRESS` only after approving, deploying and verifying the new contracts on Avalanche C-Chain. Blank or invalid addresses disable spending; there is no fallback to Brenda or Harry. Both deployments must use the existing EVO and Evo NFT addresses in `src/data/addresses.ts`, and treasury `0x9F64C4bECa7BBda647B9A755B29F7F9687bc4303`.

Before wallet transactions, the UI checks C-Chain, both treasury/token/NFT addresses, reciprocal Bertha/Hermann wiring and pause status. Contract calls are simulated before signing, with a final wallet/ownership check. An exact EVO allowance is requested if the existing allowance is insufficient. No NFT transfer approval is requested.

The Nursery connects chain wallets directly, rather than converting them to the smart account used by the existing site connector. No website sign-in is required to select owned NFTs. This first implementation supports standard chain wallets. Smart accounts are blocked from Nursery spending until their execution gas-price behavior is verified against the native VRF wrapper. Other site wallet flows are unchanged.

The ABI snapshots come from the local contracts repository `dan-dev` commit `d13f8f6`, generated by Solidity 0.8.28:

- `contracts/NPCs/Breeder_Bertha/Breeder_Bertha.sol`
- `contracts/NPCs/Hatcher_Hermann/Hatcher_Hermann.sol`

Synchronize these snapshots after any contract API change. No existing or new contract was deployed by this website change.

## Prices and asynchronous completion

For each parent: `500 EVO × 2^generation × (1 + totalBreeds)`. For generation zero the pricing breed count caps at four, matching the current contract's 2,500 EVO maximum per generation-zero parent. Other generations allow five breeds. Cooldown is `max(1, 7 - generation)` days. Parents need opposite known genders, different token IDs and a shared non-empty element.

When deployments are configured, the selector uses Hermann's canonical traits and parent reservations. `previewBreed` verifies the pair and cost again before payment. EVO is held in Bertha until the egg is minted, then transferred to the treasury.

Each breed or hatch request quotes its own randomness charge. The wallet transaction specifies the gas price used for that quote, pays at most the displayed quote plus a 10% integer-rounded buffer, and credits unused AVAX to the payer. The UI exposes credit reclamation. Network gas is additional. A zero sponsored quote remains zero; there is no advance hatching charge.

VRF fulfillment does not automatically mint or hatch. Users complete a ready breed with **Collect egg**, and a ready hatch with **Finish hatching**. Incubation starts at egg creation. Treatment costs 250 EVO, goes to the treasury and locks as soon as hatch randomness is requested. Pending breeds cannot be cancelled or rerolled after randomness commitment.

The Nursery uses a separate live query cache so bigint-valued contract results are not serialized into the site’s existing JSON cache. Contract state is rechecked after reload. Submitted breed transaction hashes and collected token IDs are saved locally, scoped to wallet, C-Chain and both deployment addresses. Pending receipt or RPC errors never appear as successful breeding. Preserve the transaction hash for recovery on another device. Eggs continue to belong to their current NFT owner.

## Local development

Use Node 22+ and the repository's pinned pnpm 10.12.3:

```sh
pnpm --filter website... install --frozen-lockfile --ignore-scripts
pnpm --filter website dev
pnpm --filter website test:nursery
pnpm --filter website exec tsc --noEmit
```

The existing site also requires Thirdweb public client/auth settings, local server auth credentials, the Evo GraphQL URL and image API configuration. Keep secrets in ignored local environment files. Do not use a production wallet key to preview this UI. Missing indexer access is reported as a loading error, rather than an empty wallet.

Before enabling spending: run the contract integration tests against the final artifacts, verify the authoritative adult import/species pool and mint role, update the indexer/metadata path for Hermann events, and exercise approvals, breed fulfillment, treatment and hatching with a funded test wallet and mock VRF on a local/test deployment. Website tests alone do not establish mainnet readiness.
